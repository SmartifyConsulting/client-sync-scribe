## Path C — Auto-confirm signups, Resend for password reset

### What changes
1. **Turn on auto-confirm email** in Supabase Auth. Signups become instant — no verification email is generated by Supabase, so the missing Send Email Hook stops mattering for signup.
2. **Password reset goes via Resend** using a dedicated edge function we invoke directly from the client (same pattern the old `auth-email-sender` used, since Supabase still won't call our hook).

### Steps
1. `configure_auth({ auto_confirm_email: true, ... })`.
2. Create `supabase/functions/send-password-reset/index.ts`:
   - Public function (no JWT).
   - Validates `{ email }` input with Zod.
   - Uses service-role `admin.generateLink({ type: 'recovery', email, options: { redirectTo } })` to mint a real recovery link.
   - Renders the existing Holarc Health branded HTML.
   - Sends via `_shared/email.ts` (Resend, `no-reply@holarchealth.com`).
   - Register in `supabase/config.toml` with `verify_jwt = false`.
3. Update `src/pages/ForgotPassword.tsx`:
   - Replace the current `supabase.auth.resetPasswordForEmail(...)` call with `supabase.functions.invoke('send-password-reset', { body: { email } })`.
   - Keep the rest of the UX identical.
4. Delete `supabase/functions/auth-email-hook/` and remove its `config.toml` entry — unused in Path C, just noise.

### Tradeoffs you accepted
- Anyone can sign up with any email (no ownership check). Email field still validated for format, not for control.
- Signup-time mistakes (typo in email) can't be corrected via verification — the user just won't be able to recover the password later.

### Reversible later
If you decide to add verification back, we re-enable Lovable Emails + add a Lovable email subdomain (Path A) — code stays mostly the same.

### What I will NOT touch
- `_shared/email.ts` Resend wiring (already correct).
- `/reset-password` page logic.
- Phone fields / signup form fields.
