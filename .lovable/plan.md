## Goal
Send Supabase Auth emails (signup confirmation, password recovery, magic link, email change, reauthentication, invite) through **Mailgun** using domain `mg.holarchealth.com`, and verify delivery.

## Approach
Use Supabase's **Send Email Hook** pointed at a Lovable edge function that calls the Mailgun HTTP API directly with `MAILGUN_API_KEY`. This bypasses Lovable Emails entirely (the pending `notify.nigeria.holarchealth.com` setup is left alone — not used).

## Steps

### 1. Secrets
Request from user via the secrets tool:
- `MAILGUN_API_KEY` — Mailgun private API key (from mailgun.com → Sending → API Keys)
- `MAILGUN_DOMAIN` — defaults to `mg.holarchealth.com`
- `MAILGUN_REGION` — `us` or `eu` (determines `api.mailgun.net` vs `api.eu.mailgun.net`)
- `SEND_EMAIL_HOOK_SECRET` — generated by Supabase when we register the hook; needed for Standard Webhooks signature verification

### 2. Edge function: `auth-email-mailgun`
New function at `supabase/functions/auth-email-mailgun/index.ts`:
- `verify_jwt = false` (Supabase calls it as a webhook)
- Verify Standard Webhooks signature using `SEND_EMAIL_HOOK_SECRET` (header `webhook-signature`)
- Parse payload: `{ user, email_data: { token, token_hash, redirect_to, email_action_type, site_url } }`
- Build branded HTML + plain-text bodies per `email_action_type` (signup / recovery / magiclink / email_change / invite / reauthentication) using HolarcHealth colors
- POST to `https://api.{region}.mailgun.net/v3/{MAILGUN_DOMAIN}/messages` with HTTP Basic auth (`api:MAILGUN_API_KEY`), form fields: `from`, `to`, `subject`, `html`, `text`
- Return 200 with `{}` on success; 4xx/5xx with error JSON

### 3. Register the hook in Supabase
Supabase Auth → Hooks → "Send Email Hook" must be enabled and pointed at:
`https://lqnnrvvrjscjceswpfal.supabase.co/functions/v1/auth-email-mailgun`
This step is **not exposed via our tools** — user does it once in the Cloud → Auth dashboard. The plan will surface the exact URL + a `<presentation-open-backend>` button so they can paste it.

### 4. DNS check for `mg.holarchealth.com`
Confirm via `dig` that Mailgun's required records exist:
- SPF TXT on `mg.holarchealth.com`
- DKIM TXT on `<selector>._domainkey.mg.holarchealth.com`
- MX (for inbound/tracking; optional for sending)
If missing, list them so user adds them at their DNS provider.

### 5. Testing
- `supabase--curl_edge_functions` POST a synthetic signature-verified payload to `auth-email-mailgun` → confirm 200 + Mailgun message ID
- Trigger a real password-reset from `/auth` → check inbox + Mailgun logs
- Tail `supabase--edge_function_logs auth-email-mailgun` for errors
